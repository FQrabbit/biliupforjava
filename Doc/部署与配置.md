# 部署与配置

[返回项目首页](../README.md)

这份文档收录 BiliUpForJava 的 Docker、WAR、录播姬网络、路径映射与 Webhook 配置。Windows 用户建议先按照 README 中的“五分钟跑起来”使用 EXE；NAS、Linux 或容器用户再从这里开始。

## 开始前需要准备

- Docker 环境，或 Java 17 及更高版本
- BililiveRecorder 或 blrec
- 一个可以正常投稿的 B 站账号
- 录播姬与本项目都能访问的录制目录
- 至少为本项目预留 1 GB 可用内存

## Docker 部署

### 容器参数

| 参数项 | 容器内默认值 | 推荐设置 | 用途 |
|---|---:|---|---|
| WebUI 端口 | `80` | `-p 12380:80` | 通过宿主机的 12380 端口访问管理界面 |
| 录制目录挂载 | 无 | `-v /path/to/recordings:/rec` | 与录播姬挂载同一个宿主机目录，并统一使用 `/rec` |
| 工作路径 | `/bilirecord` | `-Drecord.work-path=/rec` | 必须与本容器中的录制目录保持一致 |
| 内存限制 | 无限制 | `-m 1g` | 推荐至少预留 1 GB，不建议限制到 512 MB |
| 时区 | `Asia/Shanghai` | 无需修改 | Docker 镜像已经设置中国时区 |
| 重启策略 | 无 | `--restart always` | 容器退出后自动重新启动 |

### 可选 JVM 参数

这些参数通过 `JAVA_OPTS` 环境变量传入：

| 参数 | 默认值 | 推荐值 | 用途 |
|---|---|---|---|
| `-Drecord.userName` | 空 | `admin` | WebUI 登录用户名 |
| `-Drecord.password` | 空 | 自行设置强密码 | WebUI 登录密码 |
| `-Drecord.work-path` | `/bilirecord` | `/rec` | 与录制文件在本容器中的挂载目录保持一致 |
| `-Dfile.encoding` | 系统默认 | `UTF-8` | 避免中文文件名或日志乱码 |
| `-Duser.timezone` | `Asia/Shanghai` | 通常无需修改 | Java 运行时区 |

### 推荐启动命令

```bash
docker pull fqrabbit/biliupforjava:latest

docker run -d \
  --name bup \
  -p 12380:80 \
  -v /path/to/recordings:/rec \
  -e JAVA_OPTS='-Drecord.work-path=/rec -Drecord.userName=admin -Drecord.password=change_me -Dfile.encoding=UTF-8' \
  -m 1g \
  --restart always \
  fqrabbit/biliupforjava:latest
```

将 `/path/to/recordings` 换成录播姬正在使用的宿主机录制目录，并将 `change_me` 换成自己的密码。

## 直接运行 WAR

从 [GitHub Releases](https://github.com/FQrabbit/biliupforjava/releases/latest) 下载最新 WAR 文件，然后运行：

```bash
java -Dserver.port=12380 \
  -Drecord.work-path=/path/to/recordings \
  -Drecord.userName=admin \
  -Drecord.password=change_me \
  -Duser.timezone=Asia/Shanghai \
  -Dfile.encoding=UTF-8 \
  -jar biliupforjava.war
```

Windows EXE 的自行构建方式请查看 [EXE 编译指南](./exe编译指南.md)。

## 配置录播姬

选择 BililiveRecorder 或 blrec 其中一个即可。

### BililiveRecorder

- 容器安装文档：[下载使用录播姬容器镜像](https://rec.danmuji.org/install/container/)
- Webhook 说明：[录播姬 Webhook](https://rec.danmuji.org/reference/webhook/)
- 默认 WebUI 端口：`2356`

```bash
docker run -d \
  --name brec \
  -v /path/to/recordings:/rec \
  -p 2356:2356 \
  --restart always \
  bililive/recorder:latest
```

推荐文件名格式：

```text
{{ roomId }}-{{ name }}/{{ json.room_info.live_start_time | time_zone: "Asia/Shanghai" | format_date: "yyyy年" }}/{{ json.room_info.live_start_time | time_zone: "Asia/Shanghai" | format_date: "MM月" }}/{{ json.room_info.live_start_time | time_zone: "Asia/Shanghai" | format_date: "dd号" }}/{{ json.room_info.live_start_time | time_zone: 'Asia/Shanghai' | format_date: "yyyy年MM月dd号-HH点mm分ss秒开播" }}/{{ title }}-{{ "now" | time_zone: 'Asia/Shanghai' | format_date: "yyyy年MM月dd号-HH点mm分ss秒" }}-{{ partIndex | format_number: "000" }}.flv
```

### blrec

- 项目地址：[acgnhiki/blrec](https://github.com/acgnhiki/blrec)
- 默认 WebUI 端口：`2233`

```bash
docker run -d \
  --name blrec \
  -v /path/to/recordings:/rec \
  -p 2233:2233 \
  --restart always \
  acgnhiki/blrec
```

推荐文件名格式：

```text
{roomid} - {uname}/{year}年/{month}月/{day}号/{year}年{month}月{day}号{hour}{minute}{second}
```

## 配置 Docker 网络

如果录播姬与 BiliUpForJava 都运行在 Docker 中，建议将它们连接到同一个自定义网络：

```bash
docker network create bili-net
docker network connect bili-net brec
docker network connect bili-net bup
```

使用 blrec 时，将命令中的 `brec` 换成 `blrec`。

连接成功后，录播姬可以通过容器名称 `bup` 访问本项目，不需要依赖容易变化的容器内部 IP。

## 配置 Webhook

| 录播姬与本项目的位置 | 推荐地址 |
|---|---|
| 位于同一个 Docker 网络 | `http://bup/recordWebHook` |
| 位于同一局域网的不同主机 | `http://本项目主机IP:12380/recordWebHook` |
| 都直接运行在同一台主机上 | `http://127.0.0.1:12380/recordWebHook` |

不要把 BiliUpForJava 容器的临时内部 IP 写进录播姬配置。容器重建后该地址可能变化。

## 路径映射：Docker 最容易踩的坑

把录制目录想成一间仓库：

- `source` 是宿主机上的真实仓库
- `target` 是容器内部看到的门牌号
- `record.work-path` 是 BiliUpForJava 实际去找文件的起点

如果两个程序说的不是同一个仓库，或者 BiliUpForJava 拿到的门牌号在自己这里不存在，Webhook 即使发送成功，也会在后续处理时提示文件不存在。

### 两个程序都在 Docker 中

推荐让两边的 `source` 和 `target` 都保持一致：

```text
宿主机真实目录：/data/recordings
录播姬挂载：    /data/recordings:/rec
本项目挂载：    /data/recordings:/rec
本项目 work-path：/rec
```

这样同一份文件在两个容器中都叫：

```text
/rec/主播名/视频.flv
```

录播姬官方容器文档同样使用 `/path/to/storage:/rec` 作为示例。部署前建议先阅读 [录播姬容器安装文档](https://rec.danmuji.org/install/container/)。

### 录播姬在 Docker，本项目使用 Windows EXE

例如录播姬的卷映射是：

```text
D:\录播:/rec
```

那么：

- 录播姬容器内看到 `/rec/主播名/视频.flv`
- Windows 实际文件位于 `D:\录播\主播名\视频.flv`
- EXE 初始化向导中的工作路径应填写 `D:\录播`

BililiveRecorder Webhook v2 提供的是录制目录下的 `RelativePath`，BiliUpForJava 会把它拼到自己的工作路径下。字段说明可查看 [录播姬 Webhook 文档](https://rec.danmuji.org/reference/webhook/)。

### 如何快速判断映射是否正确

1. 在录播姬里找到一份刚刚录完的视频路径
2. 进入 BiliUpForJava 容器，或在 Windows 资源管理器中，从工作路径开始逐级查找
3. 确认最终能看到同一个视频文件，而不是只看到名字相似的另一个目录
4. 再触发一次测试录制，检查日志中是否还出现 `FileMissing` 或“文件不存在”

对于可能发送绝对路径的录播工具，两个 Docker 容器使用相同的 `/rec` 路径最稳妥。

## 完成 WebUI 设置

1. 访问 `http://你的服务器IP:12380`
2. 进入用户页面，登录 B 站账号
3. 添加或编辑直播间
4. 选择是否自动上传、是否删除源文件和投稿账号
5. 设置标题、标签、封面等投稿信息
6. 触发一次测试录制，确认 Webhook、目录映射和上传都正常

## 安全建议

- 设置 `record.userName` 和 `record.password`
- 不要把无密码的 WebUI 直接暴露到公网
- 公网环境优先使用 VPN、SSH 隧道或带访问控制的反向代理
- 不要在截图、日志或问题反馈中公开 Cookie、密码和真实存储路径
